Agentic job-application pipeline

Two thousand postings in.
One page out.

An orchestrator agent scans job boards, triages them, and hands every surviving posting to its own subagent. Each one tailors a one-page LaTeX resume from a personal knowledge base and refuses to ship it until the extracted text passes an ATS check.

The repository

Every node above is a directory you can open.

Skills hold the prose an agent follows; scripts hold the decisions that should never drift between runs. The split is the design — anything with fixed thresholds and set logic moved out of skill prose and into tested Python.

The verification bar

Checks that exist because a real PDF failed them.

Verification runs on text extracted from the compiled PDF, not on the PDF as a human sees it. A resume can look perfect in a viewer and still extract as garbage.

  • Enforced

    No math-mode symbols in bullets. $\to$ and $\times$ extract as glyphs glued to adjacent digits (63.4s→<100ms), which keyword matchers tokenize wrong.

  • Enforced

    No ffi/ffl words where a synonym exists. The Latin Modern OTF faces drop the ToUnicode mapping for those ligature triples, so "traffic" comes back garbled. It became "burst load".

  • Enforced

    No overfull heading row. A long repo URL beside a long project title collides with no space between cells (NumPygithub.com/...). The title gets shortened; link text stays verbatim.

  • Enforced

    Exactly one page, section headings untouched. Parsers segment on Education / Experience / Projects / Technical Skills, so those four strings are never renamed.

  • Reported

    Required-keyword coverage. Misses are reported as gaps rather than papered over. Nothing is ever invented to close one.
